# 가상 회사

내 컴퓨터의 Claude Code(`claude.exe`)를 직원으로 고용하는 로컬 웹 대시보드입니다.
API 키 없이, 이미 로그인된 claude의 구독 인증을 그대로 씁니다.

## 준비물

- Node.js 20 이상
- Claude Code CLI. 네이티브 설치(`claude.exe`)를 권장합니다. 터미널에서 `claude`를 한 번 실행해 로그인해 두세요.

## 실행

Windows는 `start.vbs`를 더블클릭하면 창 없이 서버가 켜지고 브라우저가 열립니다. 브라우저 탭을 모두 닫으면 10초 뒤 서버도 꺼집니다(업무가 진행 중이거나 결재를 기다리는 동안에는 끝날 때까지 기다립니다). 이미 켜져 있으면 브라우저만 엽니다. 서버 기록은 `data\server.log`에 남습니다.

서버 창을 보면서 실행하려면 `start.bat`을 쓰세요(창을 닫으면 서버가 꺼집니다). 다른 환경에서는 아래처럼 실행한 뒤 `http://localhost:4317` 에 접속합니다.

```
npm start
```

사용량을 쓰지 않고 화면과 흐름만 보고 싶다면 `demo.vbs`(창 없이), `demo.bat` 또는 `npm run demo`로 데모 모드를 켭니다. 실제 claude 대신 같은 프로토콜을 흉내 내는 모의 직원이 일합니다.

claude를 npm으로 설치했다면 설정 탭의 "claude 실행 파일 경로"에 npm 패키지 안의 `claude.exe` 전체 경로를 넣으세요(예: `%APPDATA%\npm\node_modules\@anthropic-ai\claude-code\bin\claude.exe`). `claude.cmd`로는 실행되지 않습니다.

## 쓰는 법

상단의 폴더 버튼으로 작업할 프로젝트를 엽니다. git 저장소를 권장합니다(변경사항 비교와 승인 시 자동 커밋에 필요).

입력창은 하나입니다. 메시지를 보내면 대표가 처리 방식을 정하고, 그 판단과 이유가 대화에 표시됩니다.

- **대화로 처리**: 질문, 설명, 탐색, 작은 수정. 평소 Claude Code처럼 개발자와 바로 대화합니다. 이어지는 메시지는 대표의 판단 없이 같은 개발자에게 바로 전달되므로, 새로운 큰 일을 맡길 때는 "새 대화"로 시작하세요. 대화 중 일이 커지면 개발자가 새 대화로 회사에 맡기라고 제안합니다.
- **개발자 단독**: 범위가 정해진 구현이나 버그 수정. 개발자가 처리하면 회사가 확인 명령(기본: package.json의 `npm test`, 설정에서 변경)을 직접 실행합니다. 사용량이 들지 않고, 실패하면 출력과 함께 개발자에게 돌려보냅니다. 통과하면 결재를 올립니다. 독립 검증은 사람의 결재가 맡습니다.
- **팀 업무**: 여러 기능에 걸친 큰 일. 아래 절차를 코드가 결정론적으로 진행합니다.

팀 업무 절차는 다음과 같습니다.

1. 기획자가 "무엇을, 왜"에 집중한 명세를 씁니다(구현 방법은 정하지 않음).
2. 개발자가 구현 방식과 검증 방법을 제안하고, QA가 이를 검토해 완료 기준 체크리스트를 확정합니다. 코드 작성 전에 "완료"의 정의를 합의하는 단계입니다.
3. 개발자가 구현합니다. 이 회사의 코드 작성자는 개발자 한 명뿐입니다(병렬 작성자 간 충돌 방지).
4. QA가 개발 과정을 모르는 새 세션에서 체크리스트대로 직접 실행해 검사합니다. 실패 항목이 있으면 근거와 함께 개발자에게 반려하고, 설정한 횟수까지 반복합니다. QA에게는 개발 과정 대신 바뀐 파일 목록만 알려줘 탐색을 줄이고, 재검사 라운드에서는 실패 항목과 새로 고친 부분만 깊게 보고 나머지는 전체 테스트로 회귀만 확인합니다.
5. 결과가 결재로 올라옵니다. 승인하면 커밋되고, 반려하면 피드백이 개발자에게 전달되어 다시 진행됩니다. 폐기하면 업무가 바꾼 파일을 시작 전 상태로 되돌립니다.

업무가 시작될 때 작업 폴더의 상태를 기록해 둡니다(사용자의 파일·스테이징·브랜치는 건드리지 않음). 그래서 승인 시 커밋에는 이 업무가 바꾼 파일만 들어가고, 업무 전부터 고치던 다른 파일은 섞이지 않습니다. 변경사항 보기도 이 업무 이후 바뀐 것(새 파일 포함)만 보여줍니다. 실패하거나 중지된 마지막 업무도 "변경 되돌리기"로 되돌릴 수 있습니다.

QA가 검사 중 파일을 고치면 코드가 이를 감지해 되돌립니다. 기존 파일을 고쳤다면 그 판정은 무효로 하고 한 번 다시 검사합니다(테스트가 남긴 새 파일은 지우기만 함).

개발자와 대화 중에 응답이 끝나기 전에 보낸 메시지는 대기열에 들어갔다가 응답이 끝나면 이어서 전달됩니다. 업무 카드에는 역할별 사용량(대표·기획자·개발자·QA)이 표시되어, 어느 단계에 사용량이 몰리는지 볼 수 있습니다. 상단의 "알림" 버튼을 켜면 창을 보고 있지 않을 때 승인 요청·결재 대기·업무 실패·응답 완료를 데스크톱 알림으로 받습니다.

입력창에 `/`를 치면 Claude Code 명령어(`/compact`, `/context`, `/model`, `/init`, 설치된 스킬 등)를 고를 수 있습니다. 명령어는 대표의 판단 없이 개발자 세션에 그대로 전달됩니다. 목록은 프로젝트를 열 때 claude에게서 받아 옵니다(사용량 0).

응답을 기다리는 동안 입력창 위에 누가 무엇을 하고 있는지와 경과 시간이 표시됩니다. 요청이 실패하면 같은 자리에 "다시 보내기"가 나타나, 원인을 고친 뒤 같은 요청을 다시 입력하지 않고 보낼 수 있습니다.

대표의 판단이 실패하면 가장 가벼운 "대화"로 진행합니다. 설정 탭의 "업무 처리 방식"에서 방식을 고정하면 판단 단계를 건너뜁니다.

사무실에서 직원을 누르면 그 직원의 작업 과정(생각, 도구 사용, 결과)을 실시간으로 볼 수 있습니다.

사무실의 방과 사람은 모두 실제로 일어나는 일을 보여줍니다(사용량 0).

| 방 | 보여주는 것 |
| --- | --- |
| 기획실 | 명세 보드(기능 수), 기획 중 표시 |
| 회의실 | 업무 단계 보드, 완료 기준 합의·QA 반려 때 모이는 곳. 회의 중에는 비서가 와서 회의록을 씀 |
| 대표실 | 처리 방식 판단, 결재 대기 시 결재판. 비서가 대표 옆자리에 있음 |
| 비서 | 승인 요청이 오면 해당 직원에게 가서 손을 듦 |
| 개발실 | 개발 팀장 작업(벽 화면). 개발 팀원 5명이 자리를 지키다가, 팀장이 서브에이전트에게 일을 맡기면 팀원이 그 일을 받아 일함(팀원이 모두 바쁘면 임시 도우미가 들어와 서서 일함) |
| QA실 | 체크리스트 칠판(항목별 통과/실패) |
| 서버실 | 확인 명령·셸 명령 실행 중 랙 점멸과 서버 엔지니어의 랙 점검, 마지막 확인 결과 경광등(실패 순간 엔지니어가 당황). 평소 엔지니어는 콘솔과 랙 사이를 오감 |
| 문서 보관실 | 쌓인 회사 문서, 승인 시 서류 보관, 폐기 시 파쇄기. 문서가 늘면 사서가 캐비닛에 꽂고, 폐기하면 파쇄기를 돌림. 평소 사서는 가끔 캐비닛을 열어 봄. 누르면 산출물 탭 |
| 라운지 | 바리스타가 있는 휴게 공간. 직원이 2분 넘게 계속 일하면 커피를 내려 자리로 가져다줌(직원당 10분에 한 번). 평소엔 소파에서 커피를 마시다 가끔 채우러 감 |

## 도구 승인

claude가 허용 목록 밖의 명령을 실행하려 하면 오른쪽 위에 승인 카드가 뜹니다. "이번만 허용", "이 세션 동안 허용", "거부" 중에 고르면 됩니다. 이 기능은 `--permission-prompt-tool stdio`로 claude의 승인 요청을 이 앱이 받아 처리하는 방식입니다.

자주 쓰는 테스트·빌드 명령은 설정 탭의 직원별 "자동 허용 규칙"에 넣어두면 묻지 않고 실행됩니다(예: `Bash(npm test *)`). 기본값으로 흔한 테스트 명령과 읽기 전용 git 명령이 들어 있습니다.

## 회사 문서 (.company/)

직원들은 프로젝트 안 `.company/` 폴더의 문서로 소통합니다. 산출물 탭에서 볼 수 있습니다.

| 파일 | 내용 |
| --- | --- |
| `spec.md`, `spec.json` | 기획자의 명세 |
| `contract.md`, `contract.json` | 합의된 완료 기준 |
| `qa/round-N.md` | 라운드별 QA 보고서 |
| `decisions.md` | 모든 직원이 따르는 기술 결정 로그 |
| `progress.md` | 진행 기록(다음 작업자에게 넘기는 인수인계) |
| `chats/`, `runs/` | 대화와 업무 기록(git 제외) |

## 설정

설정 탭에서 claude 경로, 업무 처리 방식(대표 판단/항상 대화/항상 단독/항상 팀), QA 최대 반려 횟수, 승인 시 자동 커밋, 직원별 모델·생각 강도·도구 승인 방식을 바꿀 수 있습니다. 앱 설정은 이 폴더의 `data/settings.json`에 저장됩니다.

## 사용량에 대해

팀 업무는 여러 세션을 돌리므로 단독 처리보다 사용량이 크게 늘어납니다. 대표는 애매하면 더 가벼운 방식을 고르도록 되어 있지만, 처음에는 작은 작업으로 감을 잡는 것을 권합니다. 상단의 "사용량" 수치는 claude가 보고하는 환산 비용이며, 구독 사용 시 실제 청구액이 아니라 참고치입니다.

이 앱은 본인 PC에서 공식 claude를 직접 실행하는 개인 도구입니다. 다른 사람에게 배포해 그 사람들의 claude.ai 로그인을 대신 처리해 주는 용도로 쓰면 Anthropic 약관에 어긋날 수 있습니다.

## 문제 해결

**"claude를 찾지 못함"**: 설정 탭에서 `claude.exe`의 전체 경로를 적습니다. 보통 `C:\Users\<이름>\.local\bin\claude.exe` 입니다. 터미널에서 `where claude`로 확인할 수 있습니다.

**npm으로 설치해 `claude.cmd`인 경우**: 동작은 하지만 긴 인자 전달이 불안정할 수 있습니다. `claude install`로 네이티브 버전을 설치하는 것을 권합니다.

**작업 중 "거부된 도구 사용" 알림**: 권한 모드에 따라 승인 없이 거부된 도구가 있다는 뜻입니다. 자동 허용 규칙을 추가하거나 권한 모드를 바꾼 뒤 다시 요청하세요.

**커밋이 생략됨**: git 사용자 정보가 없을 때 생깁니다. `git config --global user.name`과 `user.email`을 설정하세요.

## 보안

서버는 `127.0.0.1`에만 열리고, 다른 웹사이트에서 보낸 요청은 거부합니다. 이 서버는 claude를 실행해 파일을 수정할 수 있으므로 포트를 외부에 공개하지 마세요.

## 사무실 그래픽 교체

`public/assets/README.md`를 참고하세요. PNG 스프라이트를 `manifest.json`에 등록하면 해당 요소만 교체되고, 나머지는 기본 도트로 그려집니다.

## 구조

```
server/
  index.js        HTTP 서버, API, 실시간 이벤트(SSE)
  claude.js       claude 세션 래퍼(stream-json 입출력, 승인 요청, 중단)
  company.js      직원 상태, 대화, 업무, 승인 요청 관리
  pipeline.js     회사 업무 절차(상태 기계)
  roles.js        직원별 프롬프트와 출력 스키마
  transcript.js   claude 이벤트를 화면용 기록으로 변환
public/
  office.js       쿼터뷰 도트 사무실 렌더러
  app.js          화면 로직
tools/
  mock-claude.js  데모 모드용 모의 claude
```
